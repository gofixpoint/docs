Amika runs coding agents in rigs: isolated devbox VMs on computers you already
own or on Amika's hosted compute. You drive rigs and their agents from the web
UI, the open-source `amika` CLI, the TypeScript SDK, or the HTTP API.

## Core concepts

- **Rigs**: Isolated VMs with your repos, agent credentials, and services in
  place. Agents work in `/home/amika/workspace`. A rig can be temporary or
  persistent.
- **Hosts**: Machines you own that run rigs. The `amika-hostd` daemon registers
  a machine with Amika and runs each rig on it as a local VM with
  [smolvm](https://smolmachines.com). See
  [Bring your own compute](/guides/byoc).
- **Hosted compute**: When you don't pick a host, Amika runs the rig on a hosted
  sandbox provider.
- **Control plane**: The hosted API and web UI at `app.amika.dev`. It
  authenticates requests, stores configuration and secrets, provisions rigs, and
  forwards requests to your hosts.
- **Preset environments**: Bundled images (`coder`, `coder-plus-docker`) with
  common tooling and agent CLIs. See [Presets](/reference/presets).
- **Services**: Named network-facing ports with URL schemes, declared in
  `.amika/config.toml`. See [Services](/reference/services).
- **Snapshots**: Captured rig state you can create new rigs from. See
  [Create a snapshot](/guides/create-a-snapshot).
- **Credential discovery**: `amika secret extract` finds local coding-agent
  credentials so you can push them as Amika secrets. Rigs receive credentials
  from the control plane, not from your machine.

## Components

| Component | Purpose |
| --- | --- |
| `amika` | CLI for rigs, hosts, snapshots, services, secrets, and agent messages |
| `amika-hostd` | Daemon that turns a machine you own into a host |
| `amikad` | Daemon inside each rig that serves SSH connections and tracks injected credentials so snapshots can scrub them |
| `@amika/sdk` | TypeScript SDK for the hosted API |
| `amika-server` | Open-source HTTP server for self-hosting the API |

## Package layout

The open-source code lives in [gofixpoint/amika](https://github.com/gofixpoint/amika).

```text
go/cmd/amika          # CLI entrypoint
go/cmd/amikad         # In-rig daemon
go/cmd/amika-server   # HTTP server entrypoint
go/internal/httpapi   # REST handlers for amika-server
js/amika-hostd        # Host daemon for your own machines
sdk/typescript        # TypeScript SDK
```

## State storage

The CLI stores local state files in XDG paths by default.

See [Storage paths](/reference/storage) for exact locations.
