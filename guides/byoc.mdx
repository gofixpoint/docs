If you are an AI agent, follow this prompt:

```markdown
Help me connect my own machines to Amika, so rigs can run on them.

If the `amika` CLI is not installed, or not logged in, first read
https://docs.amika.dev/guides/agent-quickstart and follow it to set it up.

Then read https://docs.amika.dev/guides/byoc and follow it to connect my
machines. On each machine, run `amika-hostd setup --skill` after the
install, and follow the instructions that it prints. Ask me before you turn
on a runtime or create an API key.
```

The rest of this page explains each step in more detail.

Bring your own compute (BYOC) runs rigs on machines you control:

- You install the `amika-hostd` daemon on a machine.
- The daemon registers the machine with Amika as a **host**.
- Rigs you create on that host run on that machine.

The daemon connects out to Amika, so the machine needs no open port. It works
behind a home router or a firewall. You can also
[listen on a port](/guides/byoc-configure-host#listen-on-a-port) instead.

## Requirements

<Note>
- Linux (x86_64 or arm64) or macOS.
- For Linux VMs: glibc 2.34+ and KVM on Linux, or Apple silicon on macOS.
- Outbound HTTPS from the machine to Amika.
- A user-scoped Amika API key. Create one under **Settings → API Keys** at
  [app.amika.dev](https://app.amika.dev/settings/api-keys), or with the CLI
  during [setup](#set-up-a-host). A
  [listening host](/guides/byoc-configure-host#listen-on-a-port) also accepts
  an organization key.
</Note>

## Set up a host

<Steps>

<Step title="Install the daemon">

On the machine that will run rigs:

```bash
curl -fsSL https://raw.githubusercontent.com/gofixpoint/amika/main/install-amika-hostd.sh | sh
```

This installs `amika-hostd`, and Node.js if it's missing. It asks no
questions. See [Installer options](/guides/byoc-manage-hosts#installer-options).

</Step>

<Step title="Set up the host">

```bash
amika-hostd setup
```

Setup asks for:

1. The host's name in Amika.
2. Your Amika API key.
3. The [runtimes](/guides/byoc-configure-host#runtimes) the host runs. Each question says what it
   installs.

Then setup:

- Installs what each runtime needs.
- Writes the config file, `~/.config/amika-hostd/config.toml`.
- Stores your API key and a new secret key in the system keychain.

On a server with no keychain, set `secret_store = "file"` in the config file
before you run setup.

To set up without prompts, for a script or an agent, pipe the API key into
`setup --non-interactive`. Choose runtimes with `--enable` and `--disable`.
`amika auth api-key create` writes a new key to a file without printing it:

```bash
dir=$(mktemp -d)
amika auth api-key create --name my-host-hostd --scope user --out "$dir/api-key"
amika-hostd setup --non-interactive --hostname my-host --enable bare_metal < "$dir/api-key"
rm -rf "$dir"
```

`--non-interactive` asks nothing, and keeps any existing secret key. If the
hostname is invalid or no key comes on stdin, it stops and changes nothing.

<Note>
`amika auth api-key create` needs amika CLI v0.24.0 or later. Sign in as
yourself with `amika auth login`: an organization key can't create a user key.
Or create the key in the web UI and save it to a file.
</Note>

<Tip>
`amika-hostd setup --skill` prints setup steps for an AI agent. They cover
the transport, the runtimes, and how to get the API key without seeing it.
</Tip>

</Step>

<Step title="Start the daemon">

To [listen on a port](/guides/byoc-configure-host#listen-on-a-port), set `transport = "listen"`
in the config file first.

```bash
amika-hostd up
```

This registers the host with Amika and connects the daemon. There's no URL to
set up. Pass `--fg` to stay in the foreground.

</Step>

</Steps>

## Create a rig on your host

<Tabs>

<Tab title="CLI">

```bash
# Make sure that the host registered, and see its sizes
amika host list

# Create a rig on it
amika rig create --name dev-box --host my-host --size small
```

- `--size` takes one of the host's own sizes.
- Without `--host`, the rig runs on Amika Cloud.
- `--runtime` picks a [runtime](/guides/byoc-configure-host#runtimes) (`smol`, `lume` or `bare_metal`).
  Without it, the rig uses its preset's runtime.
- `--snapshot <name>` starts from a snapshot taken on the same host. See
  [Snapshots on your host](/guides/byoc-configure-host#snapshots-on-your-host).

The first `amika-hostd up` downloads the preset images in the background. A
rig created before the download finishes can time out. The daemon log shows
progress.

</Tab>

<Tab title="Web UI">

1. Open **Create a rig** at [app.amika.dev](https://app.amika.dev).
2. Under **Runs on**, change **Amika Cloud** to **Your hosts**.
3. Select **Linux VM**, **MacOS VM** for a [macOS rig](/guides/macos-rigs),
   or **Bare metal** for a [bare-metal rig](/guides/bare-metal-rigs).
4. Select your host and one of its sizes, then click **Create rig**.

A host that can't take a rig is shown but can't be selected. It shows why:
**Not responding**, **No URL yet**, or **Checking…**. The form explains the
problem under the picker, with links to **Manage hosts** and **check again**.

Your hosts are also under **Hosts** in the sidebar.

</Tab>

<Tab title="TypeScript">

Pass the host's ID as `hostId`. `amika host get <hostname>` prints the ID and
the host's sizes.

```ts
const hostId = "host_123"; // From `amika host get my-host`
const rig = await client.rigs.create({ name: "dev-box", hostId, size: "small" });
await rig.wait();
```

With `hostId`, `size` is one of the host's own sizes. `rig.hostId` and
`rig.hostname` show where a rig runs.

</Tab>

<Tab title="HTTP API">

Send the host's ID as `host_id`, and one of the host's sizes as `size`. To
pick a [runtime](/guides/byoc-configure-host#runtimes), add `runtime` (`smol`, `lume` or `bare_metal`).

```bash
curl -X POST https://app.amika.dev/api/v0beta1/rigs \
  -H "Authorization: Bearer $AMIKA_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{"name":"dev-box","host_id":"host_123","size":"small"}'
```

</Tab>

</Tabs>
