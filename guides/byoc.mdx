Bring your own compute (BYOC) runs rigs on hardware you control. You install
the `amika-hostd` daemon on a machine, it registers that machine with Amika as
a **host**, and each rig you create on that host runs there as a local VM.

Everything else stays the same. The CLI and web UI work as they do on Amika
Cloud: a rig only runs on your hardware when you ask for it by host. The VMs
and their disks stay on your machine, while creating and managing a rig goes
through Amika, which authenticates the request and forwards it to your daemon.

<Warning>
Browser previews and `rig ssh` reach the daemon directly over your tunnel, on a
credential Amika signed. Restricting the tunnel to Amika's own traffic breaks
them.
</Warning>

<Note>
The TypeScript SDK reports which host a rig is on, but cannot create one there
yet. Use the CLI or the web UI.
</Note>

## Requirements

<Note>
- Linux x86_64 or arm64 with glibc 2.34+ and KVM, or macOS on Apple silicon.
- `e2fsprogs`, only if a rig size has a disk under 20 GiB: smolvm shrinks its
  template with `resize2fs`.
- A way to expose one local port to the internet over HTTPS, such as
  [ngrok](https://ngrok.com) or
  [Cloudflare Tunnel](https://developers.cloudflare.com/cloudflare-one/connections/connect-networks/).
- An Amika API key from **Settings → API keys** at
  [app.amika.dev](https://app.amika.dev/settings/api-keys).
</Note>

Node.js and [smolvm](https://smolmachines.com), which the daemon needs, are
installed for you when the machine doesn't already have them.

## Set up a host

<Steps>

<Step title="Install the daemon">

On the machine you want to run rigs:

```bash
curl -fsSL https://raw.githubusercontent.com/gofixpoint/amika/main/install-amika-hostd.sh | sh
```

</Step>

<Step title="Store your credentials">

```bash
amika-hostd setup
```

It asks for this host's name and your Amika API key, and generates the secret
key Amika uses to reach the daemon. Secrets go in the system keychain. On a
server with no keychain, set `secret_store = "file"` in the config before
running setup. Edit the file the installer printed: the daemon reads
`$XDG_CONFIG_HOME/amika-hostd/config.toml` (`~/.config/...` by default) if it
exists and `/etc/amika-hostd/config.toml` otherwise, never both.

</Step>

<Step title="Start the daemon">

```bash
amika-hostd up
```

This registers the host with Amika, starts the daemon on `127.0.0.1:3020`, and
starts smolvm alongside it.

</Step>

<Step title="Give the host a public URL">

Amika reaches the daemon over the internet, so expose port 3020 over HTTPS and
record the URL:

```bash
ngrok http 3020                                    # in another terminal
amika-hostd register-url https://<your-tunnel-url>
```

`amika-hostd up` prompts for this URL when the host doesn't have one, so you
can paste it there instead.

<Warning>
Prefer HTTPS at the root of its own hostname on the default port, as a tunnel
URL gives. `register-url` takes a path, an explicit port or plain http and
warns: rigs and service links still work, but a browser preview that loads
root-relative assets, such as a Vite or Next.js dev server, does not.
</Warning>

</Step>

</Steps>

## Create a rig on your host

<Tabs>

<Tab title="CLI">

```bash
# Confirm the host registered, and see the sizes it offers
amika host list

# Create a rig on it
amika rig create --name dev-box --host my-host --size small
```

`--size` takes one of that host's own sizes, not the cloud size names. Omit
`--host` and the rig runs on Amika Cloud.

The first `amika-hostd up` downloads the preset images in the background, and a
rig created before that finishes can time out. The daemon logs the progress.

</Tab>

<Tab title="Web UI">

1. Open **Create a rig** at [app.amika.dev](https://app.amika.dev).
2. Under **Runs on**, switch from **Amika Cloud** to **Your hosts**.
3. Pick your host and one of its sizes, then click **Create rig**.

Your registered hosts are also listed under **Hosts** in the sidebar.

</Tab>

</Tabs>

## Configure sizes and images

The config file you set up above sets the rig sizes this host offers and the
preset image each rig boots. Every `amika-hostd up` publishes the sizes
to Amika, so the file is the source of truth for them. Preset images stay
local: the host pins the version it boots. Edit the file and restart the daemon
either way.

```toml
[sizes.small]
vcpus = 2
memory_gib = 4
disk_gib = 20

[preset_images]
amika-coder = "ghcr.io/gofixpoint/amika-coder:latest"
```

<Tip>
Keep `disk_gib` at 20 or more. Below that, smolvm doesn't cache the rig's
image, so every create downloads it again.
</Tip>

## Manage hosts

| Command | What it does |
| --- | --- |
| `amika host list` | List your organization's hosts and their sizes |
| `amika host get <hostname>` | Show one host and the sizes it offers |
| `amika host delete <hostname>` | Delete a host and its stored secret |

Hosts register themselves, so there is no command to add one. A host that
still has rigs on it can't be deleted: delete the rigs first.

To take a host offline, run `amika-hostd down` on the machine. That stops the
daemon and the VMs it is running, keeping their disks. The next `up` brings the
daemon back, but not the rigs: start those with `amika rig start`. Deleting the host record alone leaves the
machine untouched, so it registers itself again on the next `amika-hostd up`.
