---
title: "Open a sandbox in your editor"
description: "Open a running sandbox in Cursor, VS Code, Claude Desktop, or Codex over SSH."
---

`amika sandbox code` opens a remote sandbox in Cursor, VS Code, Claude Desktop,
or Codex over SSH. Cursor is the default.

## Prerequisites

<Note>
- An SSH identity. Create one with `amika secret ssh-keygen`.
- For Cursor or VS Code, its CLI (`cursor` or `code`) on your `PATH` and the
  **Remote - SSH** extension installed.
</Note>

## Open the sandbox

```bash
amika sandbox code dev-box

# Cursor is the default
amika sandbox code dev-box --editor cursor
amika sandbox code dev-box --editor vscode
amika sandbox code dev-box --editor claude
amika sandbox code dev-box --editor codex
```

Use `cursor` or `vscode` to open the repository in that editor. Use `claude` to
register the sandbox as a Claude Desktop SSH environment, then select
`Amika: <sandbox-name>` from its environment dropdown. Use `codex` to add the
sandbox as a Codex remote connection, then enable the host in **Settings >
Connections**.

For Cursor and VS Code, the command opens the repository directory. If the file
explorer is not visible, press `Cmd+Shift+E`.

## Use another Remote-SSH editor

Any editor that reads your `~/.ssh/config` and supports remote SSH can use the
Amika-managed host alias.

1. Run `amika sandbox code dev-box` once to write the sandbox alias to
   `~/.ssh/amika.conf` and include it from your SSH config.
2. Open your editor's remote-SSH host picker and select
   `<sandbox-name>.<sandbox-id>.<environment>.amika`.
3. Open the repository directory in the sandbox, typically under
   `/home/amika/workspace`.

## Use a browser

To work with an agent without a local editor, use the OpenCode web console. See
[OpenCode](/guides/opencode) for access and credentials.

## What it does

Under the hood, `amika sandbox code`:

1. Creates a direct SSH session and pins the sandbox's Ed25519 host key.
2. Builds an alias in the format
   `<sandbox-name>.<sandbox-id>.<environment>.amika`.
3. Ensures `~/.ssh/config` includes the Amika-managed `~/.ssh/amika.conf`.
4. Adds a concrete host entry so editors can discover the sandbox. An
   environment-scoped wildcard entry supplies the shared connection settings:

```ssh-config
# dev-box
Host dev-box.<sandbox-id>.app-amika-dev.amika

Host *.app-amika-dev.amika
  User amika
  IdentityFile ~/.ssh/amika_id_ed25519
  IdentitiesOnly yes
  StrictHostKeyChecking yes
  UserKnownHostsFile ~/.ssh/amika_known_hosts
  ProxyCommand amika plumbing ssh-stdio-proxy %h
  ServerAliveInterval 15
  ServerAliveCountMax 3
```

5. Opens or configures the selected editor or coding agent with the alias.

The concrete entry intentionally has no connection options. OpenSSH gets those
from the wildcard entry for the current Amika environment. This lets one config
support sandboxes from multiple control planes without sending an alias through
the wrong proxy.

## Troubleshooting

- **`cursor` or `code` CLI is not installed or not in `PATH`** — install the
  editor's shell command from its command palette.
- **`unsupported editor`** — pass one of `cursor`, `vscode`, `claude`, or
  `codex`.
- **Cursor or VS Code opens but cannot connect** — make sure its **Remote -
  SSH** extension is installed.
