---
title: "Send a message to an agent"
description: "Run Claude, Codex, or another agent inside a rig and read its response."
---

Once you have a running rig, you can drive its coding agent (Claude Code,
Codex, OpenCode, etc.) by sending a single prompt synchronously. The call
blocks until the agent finishes and returns the result.

## Prerequisites

<Note>
- A rig in the `active` / `running` / `started` state. See
  [Create a rig](/guides/create-a-rig).
- Agent credentials injected at rig-create time. See
  [Inject credentials](/guides/inject-credentials).
</Note>

## Step 1 — Send a prompt

By default the call uses Claude. Pass `--agent` / `agent` to switch agents.

<CodeGroup>

```bash CLI
amika rig agent-send dev-box "Add unit tests for the auth module"
```

```ts TypeScript
const rig = client.rigs.handle("dev-box");
const turn = await rig.send({
  message: "Add unit tests for the auth module",
});
if (turn.isError) throw new Error(turn.response);
console.log(turn.response);
```

</CodeGroup>

## Step 2 — Continue or start a fresh session

By default, both the CLI and SDK resume the most recent session for the
rig. Force a new session with `--new-session` / `newSession`, or pick a
specific one with `--session-id` / `sessionId`.

<CodeGroup>

```bash CLI
# Start fresh
amika rig agent-send dev-box "Refactor the API layer" --new-session

# Resume a specific session
amika rig agent-send dev-box "Now write the tests" \
  --session-id 3f2a...
```

```ts TypeScript
const rig = client.rigs.handle("dev-box");

// Start fresh
await rig.send({
  message: "Refactor the API layer",
  newSession: true,
});

// Resume a specific session
await rig.send({
  message: "Now write the tests",
  sessionId: "3f2a...",
});
```

</CodeGroup>

## Stream the reply (SDK)

`sendStream` takes the same request and calls your handlers as the turn runs.
`onDelta` receives reply text in order, and `onStatus` reports milestones. It
resolves with the completed turn, like `send`.

```ts
const turn = await client.rigs.handle("dev-box").sendStream(
  { message: "Explain the test setup" },
  { onDelta: (text) => process.stdout.write(text) },
);
```

## Response shape

`send` and `sendStream` return the agent's reply, the session ID it ran in,
and whether the agent reported an error.

```ts
interface AgentSessionSendResponse {
  sessionId: string;       // pass back as sessionId to continue
  sandboxId: string;       // the rig the turn ran on
  agent: string;
  response: string;        // the reply, or failure details when isError
  isError: boolean;
  isNewSession: boolean;
  createdSandbox: boolean;
  usage?: AgentSessionUsage;
}
```

See [Types](/sdks/typescript/types#agent-sessions) for `AgentSessionUsage`.

## Things to know

- **Sends block.** The call waits for the agent to finish before returning.
  The SDK uses a **10-minute HTTP timeout** for sends (the default elsewhere
  is 30 seconds). Anything that wraps the SDK (Lambda, Cloudflare Worker,
  etc.) needs at least that much runtime budget.
- **Check `isError`.** An agent failure, such as a rejected agent credential,
  returns `isError: true` with details in `response`, even though the HTTP
  request succeeded. To fix a credential problem, see
  [Inject credentials](/guides/inject-credentials).
- **Default is resume.** Without `--new-session` / `newSession` or
  `--session-id` / `sessionId`, both the CLI and the SDK continue the rig's
  current session.
