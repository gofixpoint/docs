---
title: "Manage secrets and agent credentials"
description: "Store API keys, OAuth credentials, and agent secrets in the Amika vault."
---

Amika has two kinds of secrets:

- **Generic secrets** — arbitrary `KEY=VALUE` pairs you can reference from
  `.amika/config.toml` or inject as rig env vars.
- **Provider secrets** — Claude Code / Codex credentials that get
  auto-injected into rigs so the agent runs without re-authenticating.

This guide covers both.

## Prerequisites

<Note>
- The CLI logged in (`amika auth login`), or an Amika API key for the SDK.
- For Claude / Codex pushes: the relevant credentials available on your local
  machine (config files, keychain, or in your environment).
</Note>

## Push a generic secret

Generic secrets are scoped to your user (`user`) or your org (`org`).

<CodeGroup>

```bash CLI
# Inline KEY=VALUE
amika secret push DATABASE_URL=postgres://...

# From specific env vars on your shell
amika secret push --from-env DATABASE_URL,REDIS_URL

# From a .env file
amika secret push --from-file .env

# Org-scoped (visible to your whole org)
amika secret push API_KEY=sk-... --scope org
```

```ts TypeScript
await client.secrets.create({
  name: "DATABASE_URL",
  value: "postgres://...",
  scope: "user", // or "org"
});
```

```bash HTTP API
curl -X POST https://app.amika.dev/api/v0beta1/secrets \
  -H "Authorization: Bearer $AMIKA_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{"name": "DATABASE_URL", "value": "postgres://...", "scope": "user"}'
```

</CodeGroup>

For `--from-env`, each environment-variable name becomes the Amika secret
name. For `--from-file`, each `KEY` in the file becomes the secret name. Use
that exact name in `.amika/config.toml`:

```toml
[env]
OP_SERVICE_ACCOUNT_TOKEN = { secret = "OP_SERVICE_ACCOUNT_TOKEN" }
```

<Note>
The CLI and the SDK can create, list, and update generic secrets, but not
delete them. Delete a generic secret in the web UI, or call
`DELETE /api/v0beta1/secrets/{id}` on the HTTP API. Provider secrets
(Claude / Codex) can be deleted from the CLI and the SDK too.
</Note>

## Push a Claude credential

Pushed Claude credentials are auto-injected into new rigs — no
in-rig login required.

<CodeGroup>

```bash CLI
# Auto-detect and push an OAuth credential (preferred)
amika secret claude push --type oauth

# Push an API key
amika secret claude push --type api_key

# From a specific credentials file
amika secret claude push --from-file ~/.claude/.credentials.json

# Or pass the value inline
amika secret claude push --type api_key --value sk-ant-...
```

```ts TypeScript
const claudeSecret = await client.agentCredentials.create("claude", {
  name: "personal-oauth",
  value: '{"claudeAiOauth":{...}}',
  type: "oauth", // or "api_key"
});
```

```bash HTTP API
curl -X POST https://app.amika.dev/api/v0beta1/secrets/claude \
  -H "Authorization: Bearer $AMIKA_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{"name": "personal-api-key", "value": "sk-ant-...", "type": "api_key"}'
```

</CodeGroup>

## Push a Codex credential

Same shape as Claude — only the provider segment changes.

<CodeGroup>

```bash CLI
amika secret codex push --type oauth

# API key
amika secret codex push --type api_key --value sk-...
```

```ts TypeScript
await client.agentCredentials.create("codex", {
  name: "personal-codex",
  value: "sk-...",
  type: "api_key",
});
```

```bash HTTP API
curl -X POST https://app.amika.dev/api/v0beta1/secrets/codex \
  -H "Authorization: Bearer $AMIKA_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{"name": "personal-codex", "value": "sk-...", "type": "api_key"}'
```

</CodeGroup>

## Extract local credentials (CLI only)

The CLI ships an extractor that scans your filesystem for Claude, Codex,
OpenCode, and Amp credentials and either prints them or pushes them
straight to the vault.

```bash
# Print what was discovered
amika secret extract

# Push everything that was discovered, after confirmation
amika secret extract --push

# Push only specific keys
amika secret extract --push --only ANTHROPIC_API_KEY,OPENAI_API_KEY

# Skip OAuth sources
amika secret extract --no-oauth
```

See [Reference — Secrets](/reference/secrets) for the full source-priority
table.

## List and delete

<CodeGroup>

```bash CLI
# Generic secrets — list only (no delete in CLI today)
# Use the web UI to inspect generic secrets.

# Provider secrets
amika secret claude list
amika secret claude delete <id>

amika secret codex list
amika secret codex delete <id>
```

```ts TypeScript
// Generic secrets
const all = await client.secrets.list();
await client.secrets.update(all[0].id, { value: "new-value" });
// No delete in the SDK. See the note above.

// Provider secrets
const claudeSecrets = await client.agentCredentials.list("claude");
await client.agentCredentials.delete("claude", claudeSecrets[0].id);
```

```bash HTTP API
# Generic secrets
curl https://app.amika.dev/api/v0beta1/secrets \
  -H "Authorization: Bearer $AMIKA_API_KEY"
curl -X DELETE https://app.amika.dev/api/v0beta1/secrets/<id> \
  -H "Authorization: Bearer $AMIKA_API_KEY"

# Provider secrets (use /secrets/codex for Codex)
curl https://app.amika.dev/api/v0beta1/secrets/claude \
  -H "Authorization: Bearer $AMIKA_API_KEY"
curl -X DELETE https://app.amika.dev/api/v0beta1/secrets/claude/<id> \
  -H "Authorization: Bearer $AMIKA_API_KEY"
```

</CodeGroup>
