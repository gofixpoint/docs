---
title: "Create a snapshot"
description: "Capture a configured sandbox as a reusable base image so new sandboxes boot fast."
---

A snapshot captures a configured sandbox's filesystem as a reusable base
image. New sandboxes that boot from it start with your dependencies,
tools, and environment already in place — no waiting on a fresh install
each time.

<Info>
Snapshots are a hosted-cloud feature. You can create them from the CLI, the
web UI, or the HTTP API. Creating snapshots programmatically (CLI or HTTP API)
works only against the hosted cloud — it is **not** available in local
open-source mode.
</Info>

The flow is:

1. Create a base sandbox with the setup script skipped.
2. Configure it the way you want the base to look.
3. Take a snapshot.
4. Launch new sandboxes from the snapshot, and optionally set it as the
   repository default.

## Step 1 — Create a base sandbox, skipping setup

When you build a base sandbox for a snapshot, skip the repository's setup
script. The setup script runs automatically every time a sandbox is
created. If it runs while you build the snapshot *and* again when someone
boots from that snapshot, it executes twice. Skip it now, and let it run
once at boot time later.

<Steps>
<Step title="Open the Create Sandbox dialog">
On the **Sandboxes** page, click **Create Sandbox** and select your
repository.
</Step>
<Step title="Check Skip setup script">
Expand **Sandbox Snapshot** and check **Skip setup script**, then click
**Create**.

![Create Sandbox dialog with Skip setup script checked](/images/create-sandbox-skip-setup.png)
</Step>
</Steps>

From the CLI, pass `--no-setup` to provision the sandbox with a no-op setup
script:

```bash
amika sandbox create --name base-box --preset coder --git --no-setup
```

## Step 2 — Configure the environment

Connect to the sandbox and set it up the way you want the base image to
look — install dependencies, build caches, configure tools.

```bash
amika sandbox ssh base-box
# inside the sandbox
pnpm install
```

See [SSH and connect](/guides/ssh-and-connect) for the connection options.

## Step 3 — Take the snapshot

The source sandbox must be running. Choose a capture mode:

| Mode | Value | What it does |
| --- | --- | --- |
| **Snapshot and delete** (recommended) | `scrub_and_delete` | Removes Amika-injected secrets — credential files and injected environment variables — then captures the snapshot and deletes the source sandbox. |
| **Full snapshot** | `full` | Captures everything as-is, including any secrets, and leaves the source sandbox running. |

<Warning>
A **Full snapshot** captures the filesystem as-is, so any secrets present
in the sandbox are baked into the image. Prefer **Snapshot and delete** for
shared base images.
</Warning>

Capture the snapshot from any of these surfaces:

<Tabs defaultTabIndex={0}>
<Tab title="CLI">
`amika snapshot create` is interactive by default: it prompts for the capture
mode and name, and for `scrub_and_delete` it previews the injected secrets that
will be removed and asks you to confirm.

```bash
# Interactive — prompts for mode and name
amika snapshot create --sandbox base-box

# Non-interactive — requires --mode and --name
amika snapshot create --sandbox base-box \
  --name example-repo-base --mode scrub_and_delete --no-interactive
```

Capture runs in the background. Check progress with `amika snapshot list`.
</Tab>
<Tab title="Web UI">
Open the sandbox's detail page and click **Take Snapshot**. Pick a capture
mode, give the snapshot a name you'll recognize, and confirm.
</Tab>
<Tab title="HTTP API">
`POST /sandbox-snapshots` returns `202` immediately and captures in the
background. Reference the source sandbox by `sandbox_name` (or `sandbox_id`).

```bash
curl -X POST https://app.amika.dev/api/v0beta1/sandbox-snapshots \
  -H "Authorization: Bearer $AMIKA_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{"sandbox_name":"base-box","name":"example-repo-base","mode":"scrub_and_delete"}'
```
</Tab>
</Tabs>

<Note>
A TypeScript SDK method for creating snapshots is coming soon. For now, use the
CLI or HTTP API to create snapshots programmatically.
</Note>

The snapshot moves through `capturing` → `finalizing` → `active`. Once it's
`active` it's ready to launch from.

## Step 4 — Launch from a snapshot

When you create a new sandbox, expand **Sandbox Snapshot** and pick your
snapshot from the **Start from snapshot** dropdown. The new sandbox boots
from the captured image instead of the preset.

### Set a repository default

Make every new sandbox for a repository boot from a snapshot by default —
either from the web UI or in your `.amika/config.toml`.

<Tabs>
<Tab title=".amika/config.toml">
Commit the default to your [repository
configuration](/reference/repository-configuration) so every collaborator
shares it. Add a `[sandbox]` section to `.amika/config.toml`:

```toml
[sandbox]
snapshot = "example-repo-base"
```
</Tab>
<Tab title="Web UI">
1. Go to **Repositories**: https://app.amika.dev/repositories
2. Click the repo you're configuring.
3. Under **Default Snapshot**, choose your snapshot.

The repository's **Sandbox Snapshots** table on the same page lists every
snapshot captured for the repo.
</Tab>
</Tabs>

<Note>
A default set in the web UI (stored in the database) takes precedence over
the `[sandbox]` value in `.amika/config.toml`. See the
[`[sandbox]` reference](/reference/config-toml#sandbox) for the full
resolution order.
</Note>
