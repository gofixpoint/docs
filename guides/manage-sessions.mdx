---
title: "Manage sessions"
description: "List, read, and continue agent sessions on a rig."
---

An agent session is a durable chat with a coding agent on a rig. Its
transcript is stored on the server and can outlive the rig. You pick a
session each time you send a prompt, and the SDK can also list sessions and
read their transcripts.

## Prerequisites

<Note>
A rig in the `active` / `running` / `started` state. See
[Create a rig](/guides/create-a-rig).
</Note>

## CLI: pick or start a session at agent-send time

The CLI doesn't expose session CRUD directly. To control which session a
prompt runs in, use the flags on `agent-send`.

```bash
# Start a fresh session
amika rig agent-send dev-box "Plan the migration" --new-session

# Resume a specific session
amika rig agent-send dev-box "Continue from earlier" \
  --session-id 3f2a...
```

To get a list of sessions, use the SDK or call the HTTP API directly. See
[CLI reference — agent-send](/reference/cli#agent-send) for the full flag
table.

## SDK: list, read, and continue sessions

Sessions are created when you send a prompt. There is no separate create or
update call.

### List sessions

<CodeGroup>

```ts TypeScript
const { sessions, total } = await client.agentSessions.list({
  rigRef: "dev-box",
  limit: 20,
});
for (const s of sessions) {
  console.log(s.sessionId, s.agent, s.status, s.preview);
}
```

</CodeGroup>

Sessions come back newest first. Omit `rigRef` to list sessions across all
your rigs. `limit` defaults to 50 on the server. `total` can be larger than
`sessions.length`, so keep it when showing a partial list.

### Read a transcript

<CodeGroup>

```ts TypeScript
const chat = await client.agentSessions.get(sessions[0].sessionId);
for (const m of chat.messages) {
  console.log(m.role, m.content);
}
```

</CodeGroup>

### Continue a session

A fetched session has `send`, `sendStream`, and `refresh` methods bound to it.

<CodeGroup>

```ts TypeScript
const turn = await chat.send({ message: "Continue from where you left off" });
await chat.refresh(); // Reload the transcript.
```

</CodeGroup>

You can also continue a session from its rig by passing `sessionId`:

```ts
await client.rigs.handle("dev-box").send({
  message: "Continue from where you left off",
  sessionId: chat.sessionId,
});
```

## End-to-end example

```ts
const rig = client.rigs.handle("dev-box");

// Start a new session for this task
const first = await rig.send({
  message: "Add unit tests for the auth module",
  newSession: true,
});

// Continue the same session
const second = await rig.send({
  message: "Now run them and fix any failures",
  sessionId: first.sessionId,
});
if (second.isError) throw new Error(second.response);

// Read the whole conversation
const chat = await client.agentSessions.get(first.sessionId);
console.log(chat.messages.length, "messages");
```

## Session shape

```ts
interface AgentSessionSummary {
  sessionId: string;
  sandboxId: string;           // the rig the session runs on
  sandboxName: string | null;  // null if the session outlived its rig
  agent: string;
  status: string;
  preview: string | null;
  model: string | null;
  effort: string | null;
  startedAt: string;
  endedAt: string | null;      // null while still running
  createdAt: string;
  updatedAt: string;
}
```

`agentSessions.get()` adds `messages`, the full transcript. See
[Types](/sdks/typescript/types#agent-sessions).

<Note>
Earlier SDK versions had `createSession`, `listSessions`,
`getLatestSession`, `getSession`, and `updateSession`. Those methods have
been removed. Use `client.agentSessions` instead.
</Note>
