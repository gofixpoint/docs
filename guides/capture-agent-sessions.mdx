<Note>
**Research preview.** Interfaces, storage formats, and CLI commands described
here may change before general availability.
</Note>

Every Claude Code, Codex, OpenCode, or `agent-send` run produces a session.
**Session capture** records that session as a structured, queryable history —
every message, tool call, file edit, and git commit, along with the model
used, token counts, and dollar cost.

Once captured, sessions become useful in three ways:

- **Cost and analytics.** See what your agents did, how reliably, and at what cost — sliced by user, repo, agent, or model.
- **Memory.** Search past work to recall how a similar problem was solved, what was decided, and which files were touched.
- **Mining.** Background jobs read past sessions to file follow-up tickets, encode user corrections into durable rules, and start parallel work.

Capture works the same way for every supported agent. The agent type is just
an attribute on the session — Claude, Codex, and OpenCode sessions all show
up in the same list and timeline views.

## What gets captured

For each session, capture records:

- **Messages** — every turn, in order, with the author (which user sent it) and the source (web, Slack, or API).
- **Model and usage** — model name and version, input / output / cache-read / cache-write tokens, and dollar cost per message and per session.
- **Tool calls** — tool name, argument summary, outcome, and duration.
- **File changes** — repository, path, and change kind for every file the agent touched.
- **Git commits** — hash, branch, commit message, and the turn that produced each commit.
- **Errors** — where the agent got stuck, with surrounding context.
- **Environment** — sandbox snapshot, agent CLI version, and the system prompt and rules in effect.

These items live on one ordered timeline. You can scrub through a session
and see, inline, the tool calls and file edits each message produced.

## Set up capture

Capture runs locally through a small CLI called `amikalog`. It wraps the
agent CLIs on your machine and streams events to the sink you configure.

### On your local machine

Install `amikalog`, then initialize once:

```bash
amikalog init
```

`init` detects the agent CLIs already on your machine (Claude Code, Codex,
OpenCode) and the `amika sandbox agent-send` command, and wires capture
into each. From then on, new sessions are captured automatically.

<Tip>
Existing sessions started before `amikalog init` are not retroactively
captured — only new sessions from that point on.
</Tip>

### On an Amika sandbox

Sandboxes have `amikalog` pre-installed and capture enabled by default. To
turn it off for a sandbox, set `capture.enabled = false` in its
`.amika/config.toml`:

```toml
[capture]
enabled = false
```

## Where sessions are stored

Capture supports two sinks. Pick one at `init` time; switch later with
`amikalog init --sink ...`.

### Local files (default)

By default, `amikalog` writes one JSONL file per session to
`~/.local/share/amikalog/sessions/`. Each line is a single event — a
message, tool call, file change, or commit. This sink is free, works
offline, and is easy to grep:

```bash
# Find every commit a session produced
jq 'select(.event_type == "commit")' \
  ~/.local/share/amikalog/sessions/as_3f2a....jsonl
```

<Info>
A SQLite sink is in the works for faster local querying. Until then, JSONL
plus `jq` or `grep` is the supported path.
</Info>

### Stream to Amika

Sign in with `amika auth login`, then re-init with the Amika sink:

```bash
amikalog init --sink amika
```

Events stream to Amika, where they're indexed and made available through
the web UI, the CLI, and search. Streamed sessions are reachable across
your machines and the rest of your organization, subject to your access
controls.

## View and use captured sessions

### In the web UI

A **session browser** lives in [app.amika.dev](https://app.amika.dev) under
**Sessions**:

- **List view** — every session with its title, agent, repo and branch, status, cost, commit and file counts, participants, and timestamps. Filter by repo, agent, user, date, or cost.
- **Timeline view** — the diarized event stream for a single session. Messages, tool calls, file changes, and commits inline in order. Each commit links to its diff or PR; each turn shows its own cost.
- **Cost dashboard** — spend by organization, user, repo, agent, and model over time.

### From the CLI

List recent sessions:

```bash
amika sessions list
```

Pull a session's filesystem locally — its messages, events, and any
artifacts it produced — to a directory you choose:

```bash
amika sessions fetch as_3f2a... ./past-session
```

The fetched directory mounts cleanly into a new sandbox, so an agent in a
fresh sandbox can read past work as files:

```bash
amika sandbox create review-box \
  --mount ./past-session:/sessions/auth-refactor:ro
```

### From an agent

Capture exposes **search** and **get session detail** tools over MCP, so an
agent or background job can query prior sessions as part of its own run.
See [MCP integrations](/guides/mcp-integrations).

## Multi-user sessions

A single session can have more than one author. When two people drive the
same sandbox — for example, one from the web UI and one from Slack —
capture records which user sent each message and which surface it came
from. The session itself stays a single record; the per-message
attribution makes "who asked for what" answerable later.
