If you are an AI agent, follow this prompt:

```markdown
Help me make my own machines bare-metal rigs in Amika.

If the `amika` CLI is not installed, or not logged in, first read
https://docs.amika.dev/guides/agent-quickstart and follow it to set it up.

Then read https://docs.amika.dev/guides/bare-metal-rigs and follow it. On
each machine, run `amika-hostd setup --skill` after the install, and follow
the instructions that it prints. Turn on only the `bare_metal` runtime,
unless I ask for VMs too. Ask me before you create an API key.
```

The rest of this page explains each step in more detail.

A bare-metal rig is your own machine, used directly as a rig, with no VM.
Amika gives you SSH to it and lists it with your other rigs. Use it for a
workstation or server you've already set up and want to keep as it is.

A bare-metal rig runs on a [BYOC host](/guides/byoc). A host can run a
bare-metal rig alone, or alongside VM rigs.

## How it differs from a VM rig

Amika changes nothing on the machine. It copies no files, secrets or settings
to it.

| Feature                                                   | VM rig on a host | Bare-metal rig       |
| --------------------------------------------------------- | ---------------- | -------------------- |
| Rigs per host                                             | Many             | One                  |
| `amika rig ssh` and editors over SSH                      | Yes              | Yes, as your account |
| Repository clone, setup and start scripts                 | Yes              | No                   |
| Secrets, environment variables and agent credentials      | Yes              | No                   |
| MCP integrations and services                             | Yes              | No                   |
| Presets, sizes and snapshots                              | Yes              | No                   |
| Web terminal                                              | Yes              | No                   |
| `amika send`, agent sessions and command runs             | Yes              | No                   |

- SSH sessions log in as the account that runs `amika-hostd`, not as `amika`.
- Sessions start in that account's home directory.
- Amika never runs commands as root on the machine.

<Warning>
Anyone in your organization with a registered SSH key can log in to a
bare-metal rig as your account. Only use a machine your organization can
share.
</Warning>

## Requirements

- macOS or Linux. Windows is not supported.
- An `sshd` binary. macOS has one. On Linux, install `openssh-server` if it's
  missing. The system sshd service doesn't need to run: Amika starts its own
  on a loopback port.
- Your home directory, and each directory above `amika-hostd`'s state
  directory, must not be writable by group or others. sshd refuses them
  otherwise. Setup names any directory that fails, and the `chmod` to fix it.
- A user-scoped Amika API key, as for any [BYOC host](/guides/byoc#requirements).

## Set up the machine

<Tabs>

<Tab title="New host">

1. Install the daemon:

   ```bash
   curl -fsSL https://raw.githubusercontent.com/gofixpoint/amika/main/install-amika-hostd.sh | sh
   ```

2. Set up the host. When setup asks about runtimes, answer no to Linux VMs
   (`smol`) and yes to this machine (`bare_metal`). Setup checks the machine,
   installs `amikad`, and prints the CPUs, memory, disk and SSH account it
   found:

   ```bash
   amika-hostd setup
   ```

   Without a terminal, run
   `amika-hostd setup --non-interactive --enable bare_metal --disable smol`,
   and pipe the API key into it. See [Set up a host](/guides/byoc#set-up-a-host).

3. Start the daemon:

   ```bash
   amika-hostd up
   ```

</Tab>

<Tab title="Existing host">

If the machine already runs `amika-hostd` for VM rigs, turn on the
`bare_metal` runtime:

```bash
amika-hostd capabilities update --enable bare_metal
```

This checks the machine like setup does, installs `amikad`, updates the
config file, and reloads the daemon. If a check fails, nothing changes. Your
VM rigs keep running.

</Tab>

</Tabs>

Check that the host shows the runtime:

```bash
amika-hostd capabilities get   # on the machine: the runtimes that are on
amika host list                # the RUNTIMES column shows bare_metal
amika host get my-host         # shows the SSH user and the machine's resources
```

## Update the host

Each `amika-hostd` release pins one `amikad` version. To get a newer
`amikad`, update `amika-hostd`:

1. Run the installer again. It keeps your config and secrets:

   ```bash
   curl -fsSL https://raw.githubusercontent.com/gofixpoint/amika/main/install-amika-hostd.sh | sh
   ```

2. Restart the daemon. `up` installs the new `amikad`:

   ```bash
   amika-hostd down
   amika-hostd up
   ```

3. Check the version with `amika-hostd version`.

<Warning>
`amika-hostd down` also stops the host's VM rigs. Their disks are kept. Start
them again with `amika rig start`.
</Warning>

## Create the rig

A bare-metal rig takes only a name.

<Tabs>

<Tab title="CLI">

```bash
amika rig create my-workstation --host my-host --runtime bare_metal
```

- If `bare_metal` is the host's only runtime, you can leave out `--runtime`.
- Don't pass a preset, size, snapshot, repository, secret or agent option. The
  create fails with `bare_metal_unsupported_option`.
- The CLI ignores the repository in your current directory.

</Tab>

<Tab title="Web UI">

1. Open **Create a rig** at [app.amika.dev](https://app.amika.dev).
2. Under **Runs on**, select **Your hosts**.
3. Select **Bare metal**, then select your host.
4. Type a name, then click **Create rig**.

The form shows the machine's CPUs, memory and disk, and no other options. A
host that already has a bare-metal rig is grayed out, with that rig's name.

</Tab>

<Tab title="HTTP API">

Send `name`, the host's ID as `host_id`, and `"runtime": "bare_metal"`. Send
no other fields.

```bash
curl -X POST https://app.amika.dev/api/v0beta1/rigs \
  -H "Authorization: Bearer $AMIKA_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{"name":"my-workstation","host_id":"host_123","runtime":"bare_metal"}'
```

</Tab>

</Tabs>

A host has at most one bare-metal rig. A second one fails with
`409 host_rig_limit`.

## Connect to the rig

Use SSH as for any rig. See [SSH and connect](/guides/ssh-and-connect).

```bash
amika rig ssh my-workstation
```

- In the web UI, the **Terminal** tab has only a **Connect via SSH** button.
  A bare-metal rig has no web terminal.
- Register your SSH key with Amika before you create the rig. If you add a key
  later, stop and start the rig to pick it up.

## Stop and delete the rig

- `amika rig stop` stops the SSH bridge. The machine keeps running.
- `amika rig start` starts the SSH bridge again.
- `amika rig delete` removes the rig and the bridge's state. Your files and
  settings on the machine stay as they are.

To stop offering bare metal on the host, delete the rig, then run
`amika-hostd capabilities update --disable bare_metal`.

To remove `amika-hostd`, see
[Uninstall the daemon](/guides/byoc-manage-hosts#uninstall-the-daemon). It stops `amikad`
and its sshd. If you also remove the state directory, it deletes the rig's SSH
host keys and authorized keys. Your own `~/.ssh` and the system sshd are not
touched.
